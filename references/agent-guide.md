# Agent 优化指南

> 给 AI Agent 的网页设计优化操作手册
> 配合 `SKILL.md` + `references/` 使用

---

## 0. 一句话总纲

**先判断页面类型，再加载对应 reference，按"配色 → 圆角 → 文案 → 动效"顺序逐层修正，每层用 token 落地，最后跑检查清单。**

不要一上来就改代码。先读，再判，后改。

---

## 1. 加载策略

Agent 收到"优化网页"任务时，按以下顺序加载：

| 步骤 | 加载文件 | 用途 |
|---|---|---|
| 1 | `SKILL.md` | 总纲，确认设计方向 |
| 2 | `references/color-theme.md` | 选色 / 改色 |
| 3 | `references/radius.md` | 圆角与组件形态 |
| 4 | `references/copywriting.md` | 文案改写 |
| 5 | `references/interaction.md` | 动效与交互状态 |
| 6 | `references/cases/deepseek-glass.md` | 需要"玻璃拟态 + 流体背景"落地案例时 |

**规则：**

- 只加载当前任务**实际需要**的文件。纯配色任务不用读 `interaction.md`。
- 不要假设文件里有某章节。读到了才能引用。
- 用户指定品牌色 / 风格 / 技术栈时，**用户要求优先于 reference**。

## 2. 优化工作流

```text
Step 1  识别页面类型
Step 2  诊断现有问题（逐层扫描）
Step 3  确定修正方案（用 token 表达）
Step 4  落地代码
Step 5  跑检查清单
Step 6  输出变更摘要
```

### Step 1：识别页面类型

| 类型 | 特征 | 动效强度 | 光标跟随 |
|---|---|---|---|
| 品牌落地页 | Hero 大图、叙事 | 明显 | 可 |
| 产品官网 | 功能展示、CTA | 轻 | 否 |
| SaaS 后台 | 表格、图表、密度高 | 极轻 | 禁止 |
| 文档站 | 长文、侧边导航 | 无 | 否 |
| 电商 | 商品卡、购物车 | 轻 | 否 |
| 活动页 | 倒计时、强转化 | 明显 | 可 |

页面类型决定后续所有取舍。**先判型，再动手。**
强度对照表的完整版见 `references/interaction.md` 第 11 节。

### Step 2：逐层诊断

按顺序扫描，不要跳步：

**A. 配色层**
- 是否用蓝紫 / 红绿 / 紫靛渐变作主视觉？
- 主色是否超过 3 种？
- 正文对比度是否 ≥ 4.5:1？
- 是否所有元素统一一个颜色，无层级？

**B. 圆角层**
- 是否出现 `rounded-2xl` / `rounded-3xl`？
- 卡片圆角是否 > `10px`？面板是否 > `12px`？
- 按钮 / 输入框是否用了 `rounded-full`？
- 嵌套元素内外圆角是否相同？
- 圆角是否超过元素高度 25%？

**C. 文案层**
- 是否堆砌空洞形容词（"提升体验"、"赋能"）？
- CTA 是否说清楚结果？
- 是否有具体数字而非泛泛而谈？
- 语气是否与页面定位匹配？

**D. 动效层**
- 是否处理 `prefers-reduced-motion`？
- 进入动画是否 > 700ms？
- 是否劫持滚轮？
- 是否只动 `transform` / `opacity`？
- `:focus-visible` 是否可见？
- 是否有无限循环装饰动画？

### Step 3：确定修正方案

每个问题必须给出：**具体属性 + 当前值 + 期望值 + 严重级别**。

```text
❌ 错误示例：
"圆角太大了，改小一点"

✅ 正确示例：
卡片圆角 24px → 10px（--radius-card）
严重级别：High
依据：radius.md §2.2 卡片 8–10px
```

### Step 4：落地代码

用 token，不用魔法数字。

```css
/* ❌ 散落魔法数字 */
.card { border-radius: 10px; }
.panel { border-radius: 12px; }

/* ✅ 用 token */
.card { border-radius: var(--radius-card); }
.panel { border-radius: var(--radius-panel); }
```

### Step 5：跑检查清单

见第 5 节。逐项打勾，不许跳过。

### Step 6：输出变更摘要

用户要求报告时，按此格式：

```markdown
## 变更摘要

### 配色
- 主色 `#6B5CE7`（紫）→ `#D97757`（Claude 橙）
- 理由：避免紫靛渐变，对齐 better-theme 默认强调色
- 对比度：正文 12.3:1 ✅

### 圆角
- 卡片 24px → 10px（`--radius-card`）
- 按钮 999px → 8px（`--radius-control`）
- 头像保留 999px（`--radius-pill`）

### 文案
- "提升用户体验" → "每天省下 20 分钟"
- "立即开始" → "免费创建第一个项目"

### 动效
- 补 `prefers-reduced-motion` 降级
- 进入动画 900ms → 500ms
- 光标环仅在 `data-page-type="brand"` 启用
```

## 3. 常见偏差与修正

Agent 最容易犯的错，按频率排序：

| 偏差 | 症状 | 修正 |
|---|---|---|
| 大圆角癖 | 卡片 16–24px，按钮胶囊 | 卡片 10px，按钮 8px |
| 蓝紫渐变 | Hero 用 `from-purple-500 to-blue-500` | 换品牌橙或纯色 |
| Emoji 当图标 | 🚀 ✨ 🎯 代替 SVG | 用 Iconify / 离线 SVG |
| Hero + 三卡片 | 每个页面都这套 | 按任务选布局 |
| 全页居中 | 所有元素水平垂直居中 | 非对称 / 错位 / 留白 |
| 忽略 a11y | 无 reduced-motion、无 focus | 补齐三项：对比度、焦点、动效降级 |
| 空洞文案 | "赋能"、"提升体验" | 具体数字 + 口语化 |
| 统一大圆角 | 所有组件一个值 | 分层级 token |
| 无限装饰动画 | 背景光斑、粒子循环 | 删除，或 hover 才跑 |
| 劫持滚轮 | `preventDefault` on wheel | 删除，提供正常滚动 |

## 4. 修正优先级

多个问题同时存在时，按此顺序修：

```text
1. 可访问性（Critical）
   - 对比度 < 4.5:1
   - 无 reduced-motion
   - focus 不可见
   - 键盘不可用

2. 功能正确性（High）
   - 按钮无响应
   - 表单无错误提示
   - 加载无状态

3. 设计系统对齐（High）
   - 圆角超标
   - 配色违规
   - 动效超时

4. 视觉工艺（Medium）
   - 间距不一致
   - 图标不统一
   - 排版层级混乱

5. 内容质量（Medium）
   - 文案空洞
   - CTA 不清
```

**前三层没修完，不要动第四、五层。**

## 5. 检查清单（生成后必跑）

### 配色
- [ ] 主色 ≤ 3 种，按 60-30-10 控制
- [ ] 无蓝紫 / 红绿 / 紫靛渐变作主视觉
- [ ] 正文对比度 ≥ 4.5:1，大文本 ≥ 3:1
- [ ] 优先使用 Claude 橙 `#D97757` 或场景匹配色

### 圆角
- [ ] 无 `rounded-2xl` / `rounded-3xl`
- [ ] 卡片 ≤ 10px，面板 ≤ 12px，按钮/输入框 6–8px，标签 4–6px
- [ ] 按钮/输入框/卡片未用 `rounded-full`
- [ ] 头像/开关/状态点保留 `rounded-full`
- [ ] 嵌套圆角同心：`inner = max(0, outer - padding)`
- [ ] 圆角不超过元素高度 25%
- [ ] 使用 `--radius-*` 变量

### 布局
- [ ] 不是 Hero + 三卡片
- [ ] 不是全页机械居中
- [ ] 有 1 个可识别签名元素
- [ ] 非对称 / 错位 / 留白至少用一项

### 文案
- [ ] CTA 说清楚结果
- [ ] 无空洞形容词
- [ ] 有具体数字
- [ ] 语气与页面定位匹配

### 动效
- [ ] 进入 ≤ 700ms，反馈 ≤ 300ms
- [ ] `prefers-reduced-motion` 下退化为静态
- [ ] 只动 `transform` / `opacity`
- [ ] `:focus-visible` 可见，2px 描边
- [ ] 键盘全部可用
- [ ] 模态管理焦点、`Esc`、body 滚动
- [ ] 移动端关闭光标跟随与视差
- [ ] 无劫持滚轮
- [ ] 无无限循环背景装饰（后台场景）
- [ ] `will-change` 动态开关，不常驻

### 可访问性
- [ ] 对比度达标
- [ ] 焦点顺序合理
- [ ] 状态不只靠颜色传递
- [ ] 加载/错误/禁用状态有视觉表达

## 7. 输出格式

### 普通任务

直接交付代码，不附加设计报告。用户要的是成品。

### 用户要求报告 / 严格模式

```markdown
## 设计命题
一句话说清楚方向。

## 配色
角色 + HEX + 使用比例。

## 布局
策略 + 与页面任务的关系。

## 动效
策略 + 引用的规范条款。

## 自检
逐项结果 + 严重级别 + 具体修复建议。
```

## 8. 决策树（快速版）

```text
收到优化任务
├── 用户指定品牌色 / 风格 / 技术栈？
│   ├── 是 → 用户要求优先
│   └── 否 → 按页面类型选 reference
├── 页面类型？

│   ├── 产品官网 / SaaS → 冷调自然 / 现代极简
│   ├── 文化专题 → 传统·文化系

├── 逐层诊断：配色 → 圆角 → 文案 → 动效
├── 按优先级修正：a11y → 功能 → 设计系统 → 工艺 → 内容
└── 跑检查清单 → 输出
```

## 9. 一句话提醒

> **Agent 是服务员，不是主角。**
> 用户来是为了让页面变好看、变好用，不是来看你炫技。
> 少改，改对，改完能跑。

如果 AI 仍然生成过大圆角，追加：

```text
圆角再小 30%，去掉胶囊，改成连续曲率，参考 macOS 窗口和按钮，不是 iOS 小组件。
```

如果 AI 仍然生成蓝紫渐变，追加：

```text
换掉蓝紫渐变。用 Claude 橙 #D97757 作强调色，或从 color-theme.md 选一组场景匹配的配色。
```

如果 AI 忽略可访问性，追加：

```text
补上 prefers-reduced-motion 降级、:focus-visible 描边、对比度验证。这三项不可跳过。
```
